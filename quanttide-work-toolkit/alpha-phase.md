# 量潮知识工作标准库开始内测

这是我们第一个标准库级别的工具库，代码开源在 GitHub 仓库 quanttide/quanttide-work-toolkit，Rust 和 Dart 包已经发布到官方镜像。

## 知识工作标准库的建模思路

核心领域模型可以概括为 3P 模型：
- Piece 组：材料 Material，产物 Artifact
- Process 组：任务 Task，工作流Workflow
- Place 组：工作区 Workspace，工作台 Workbench

用这组核心领域模型讲故事：

用户有一组材料（比如飞书消息、飞书文档等），放在公司工作台里属于自己的工作区，设计一个分步骤处理的工作流（比如根据时间排序信息、梳理主线、写成文档等），执行任务并验收，最后得到自己想要的产物（比如一份工作手册）。

这组概念很好的支持了“以工作流为中心”的可复用、可验收的知识工作方式。

## 标准库的工程难点及解决方案

虽然核心故事往往足够简单，但是支持主干故事需要的细节非常多，人类架构师很难面面俱到。

执行方案的 AI 往往缺乏业务建模能力，这是由生成式 AI 在上下文学习的普遍短板导致的。

这个时候，往往会出现人类一套、AI 一套的尴尬状况，导致 AI 明明做出来了可用的效果，但是人类很难理解，也很难给 AI 导航。

为了解决这个问题，我们对 AI 进行了一系列系统的工程规范约束，包括：
- 文档、测试、代码严格对齐。
- 文档保证可读性良好，人类可以准确理解。
- 单元测试覆盖率达到接近 100%。
- 代码模块根据领域分包、根据分层模型分模块。
- 全面改善 API 设计风格，移除坏味道的 API 设计。
- 提炼过程中发现的新的隐式模型。
- 对齐集成测试和案例库。
- 其他可以提高工程质量的方式。

我们在单个对话里使用 DeepSeek v4.1 flash，通过 20 亿 token、2000 次消息、50 元费用，成功对齐了人类建模和 AI 实现，且人类几乎没有过度介入具体工作步骤。

这意味着只需要大幅提高工程控制水平，制作高质量领域标准库的门槛将会从资深架构师到更多直觉优秀的新人开发者。
